# First-release acceptance map

This document maps R01–R26 in the preserved [handoff](../EXERCISE_BIOMECHANICS_HANDOFF.md) to the application and its verification routes. It describes implemented behavior and its limits; an implementation reference or test definition is not evidence that every browser, machine, or physiological interpretation has been validated.

The release has six quantitative model families: pullover, elbow flexion, elbow extension, lateral raise, shoulder fly, and hip extension. The twelve initial scenarios share family-specific geometry and force calculations, with additional educational pullover presets. The dedicated pullover machine is a separate, explicitly non-quantitative illustration. The active mechanics version is declared by `MODEL_VERSION` in [engine.ts](../src/engine.ts).

## Verification commands

The handoff's separate exploration/usable-range behavior is implemented by [usableRange.ts](../src/usableRange.ts) and [motionConstraint.ts](../src/motionConstraint.ts). Users can choose a clear connected interval, retain the original range, and synchronize only where both panels satisfy represented geometry. Unknown mechanisms and slack cable routing remain unavailable for this constraint. This is a geometric model restriction, not a personal range-of-motion or safety assessment.

Run numerical/state/library/analysis/parser checks and the production build from the repository root:

```sh
npm test
npm run build
npm run test:e2e
npm run test:pwa
```

The offline suite uses the production build, not the Vite development server. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` only when using an existing Chromium executable. The test files and configurations linked above define the acceptance routes; use the release run's actual terminal or CI results for pass/fail counts, rather than treating this traceability table as a blanket pass certificate.

Additional device acceptance should record the Android device, OS/browser version, portrait and landscape dimensions, installation result, offline reopen after cache preparation, control latency, and animation responsiveness. The handoff's roughly 100 ms control-update target is a measurement target, not a claimed benchmark for unspecified hardware.

## Model and product boundaries

- **Body estimates are illustrative.** The reference proportions are an editable example, not an individual anthropometric prediction or population percentile. Measurement landmarks are approximations to model references. Height does not imply flexibility, strength, pain-free movement, muscle insertions, or training suitability.
- **Joint paths are prescribed.** The models do not solve whole-body dynamics, muscle recruitment, scapular motion, balance, ground reaction forces, or exact internal joint loads. Lower-limb support checks preserve represented segment lengths; they do not establish that every drawn pose is comfortable or stable.
- **Rigid-bar grip closure is constrained.** The symmetric pullover solver preserves segment lengths, actual elbow bend and hand/bar closure for feasible grip widths. Incompatible grip/bar widths are flagged. This is a constrained solver, not a full shoulder/scapular anatomical model or an inferred per-shoulder sharing of a bar load.
- **Contact is bounded by what is represented.** Backrest tests do not certify clearance from a user's seat, uprights, feet, body, frame, guides, or other equipment. The represented harmonic cable/bar paths are partitioned at analytic box-face and cable-edge-plane candidates, then checked and refined; tests cover narrow contact intervals and isolated tangency. This does not certify a real installation or contacts with unrepresented objects.
- **Load properties must be supplied.** Actual force, selected mass and transmission factor, free-weight mass, slack/unknown states, and optional segment masses remain explicit. Friction, inertia, cable elasticity, changing machine cams, and post-contact cable rerouting are not inferred. Unknown mechanisms stay non-quantitative.
- **Stored data is local to the browser/origin.** Export is the portable backup mechanism. Library imports and snapshots are bounded and validated; known older-model data is backed up before replacement. A browser clearing storage or an operating system evicting offline caches cannot be prevented by the application.
- **The training import is a selection aid.** It recognizes supported labels, retains original/ambiguous/unmatched names, and accepts explicit user choices. It does not infer forces from training loads or turn the application into a workout log or coaching service.
- **Mechanical differences are not physiological rankings.** No hypertrophy score, exact muscle-tension estimate, EMG proxy, or universal optimal setup is computed. Advanced anatomical models, measured commercial-machine profiles, and training-study conclusions require their own data and validation.

These boundaries describe the implemented models and the evidence needed for additional claims. They do not replace verification of the first-release behavior above.
